# Architecture

## Repository layout

```
framework-core/
├── index.php                  # Entry point → redirects to src/index.php
├── pons-settings.php          # Runtime DB credentials (gitignored)
├── copiacore.php              # Syncs core files into a child project
├── deploy.php                 # Deploy via FTP/FTPS/SFTP (see DEPLOYMENT.md)
├── data/
│   ├── lang/                  # Translation files (*.lang.txt)
│   ├── logs/                  # App logs (gitignored)
│   ├── dbimg/                 # Uploaded media (gitignored)
│   └── basic_theme/           # Default theme assets (login, layout, css)
└── src/
    ├── index.php              # Main router: loads the user's default component
    ├── login.php / logout.php / resetpassword.php
    ├── _include/              # Core framework classes
    ├── componenti/             # Application modules (only the core ones live in this repo)
    ├── template/               # Shared comode.js, controlloform.js, stile.css
    ├── assets/                 # Third-party libraries (jquery, tinymce, viewer) — gitignored
    ├── lib/                    # Hand-vendored libraries (filemanager, php-zip) — gitignored
    ├── icons/, images/
    └── vendor/                 # Composer (gitignored, see CONFIGURATION.md)
```

## Core files (`src/_include/`)

| File | Purpose |
|------|---------|
| `config.php` | Loads settings, defines constants, includes all classes. The framework's version changelog lives as comments at the top of this file. |
| `comode.php` | Utility library (~1700 lines): DB helpers, template/i18n handling, validation, uploads, dates. See [COMODE-HELPERS.md](COMODE-HELPERS.md). |
| `ambiente.class.php` | `Ambiente` class: template engine, global variable replacement (`##placeholder##`). |
| `session.class.php` | `Session` class: wrapper around `$_SESSION` with an MD5 prefix to isolate multiple installations on the same domain/server. |
| `login.class.php` | `Login` class: authentication against `frw_utenti`, menu handling. |
| `login-custom.class-example.php` | Example custom login extension (per-project extension point). |
| `crudbase.class.php` | `CrudBase` class: generic base for C.R.U.D. behavior, extended by components' manager classes. |
| `grid.class.php` | `Grid` class: rendering of paginated/filterable lists. |
| `formcampi.class.php` | `pezzoDelForm` class and subclasses: form field generators. See [FORMS.md](FORMS.md). |
| `logger.class.php` | `logger` class: file-based logging with rotation, hooked into `set_error_handler`. |
| `cryptor.class.php` | `Cryptor` class: encrypts/decrypts strings (used for tokens, ids in URLs, etc.). |
| `botfilter.php` | `dieIfBotOrSuspiciousTraffic()`: blocks known bot/scraper user-agents (typically used on public pages, e.g. the ad server). |
| `ajax.lang.php` / `ajax.menu.php` | Shared AJAX endpoints: current language labels as JSON, and the logged-in user's menu markup. |
| `constant_intelliphense.php` | Declares (with a sentinel value `"DEFINE_ERROR"`) the constants normally set at runtime from the DB (`frw_vars`), purely to avoid editor/Intelephense warnings. Should be regenerated by hand if the list of variables changes. |

## Component MVC pattern

Each component lives under `src/componenti/{name}/` with this structure:

```
componenti/{name}/
├── index.php               # Controller: reads $command (the "op" parameter), executes it, renders the template
├── _include/
│   └── {name}.class.php    # Model/Manager, typically extends CrudBase
├── ajax/  (or ajax.*.php in root)   # AJAX endpoints, JSON response
└── template/
    ├── elenco.html          # List
    ├── dettaglio.html       # Detail/edit form
    └── dettaglio.js         # Form-specific JS (if present)
```

**Request flow:**
1. `src/index.php` → reads the user's default component from the DB → redirects.
2. `componenti/{name}/index.php` → reads `op` (command) and `id` (parameter) via `getpost()`/`get()` → instantiates the manager class → executes → renders.
3. If no command produces `$html`, the list view is shown (`$obj->elenco(...)`).
4. The final template always goes through `translateHtml()` before being printed, to resolve the `{LABEL}` placeholders.

### Standard CRUD commands (the `op` convention)

Observed in `frwvars` and repeated across virtually every CRUD component:

| `op` | Action |
|------|--------|
| `aggiungi` (add) | Shows the insert form (`getDettaglio()` with no id) |
| `aggiungiStep2` (add, step 2) | Receives the POST, inserts (`updateAndInsert($_POST, $_FILES)`) |
| `modifica` (edit) | Shows the edit form (`getDettaglio($id)`) |
| `modificaStep2` (edit, step 2) | Receives the POST, updates (`updateAndInsert($_POST, $_FILES)`) |
| `elimina` (delete) | Deletes a record (`deleteItem($id)`) |
| `eliminaSelezionati` (delete selected) | Bulk delete from the list view (`eliminaSelezionati($_POST)`) |

These are literal PHP values used by the codebase — kept in Italian rather than translated, since renaming them would misrepresent the actual code.

Manager class return conventions:
- `"0"` → not authorized → `returnmsg("Non sei autorizzato.","jsback")` ("You are not authorized")
- a string containing `"-1|message"` → validation error → shown as an error message
- otherwise → the form HTML, or `returnmsgok(...)` with the client-side action to run (`reload`, `load index.php`, ...)

This pattern is implemented by `CrudBase` and reused/extended by every component's manager class — new components should follow it instead of reinventing command handling.
