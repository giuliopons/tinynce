# Language files

Location: `data/lang/`.

## Actual format

**Quoted CSV format** (not tab-separated, despite earlier versions of this documentation
stating otherwise — verified against the actual files in this repo):
`"LABEL","TRANSLATION"`, with an optional third column carrying a version (e.g.
`"...","...","4.2.8"`). The first line is the header `LABEL,TRANSLATION`. Files use CRLF
line endings.

```
LABEL,TRANSLATION
"Proceed","Proceed"
"MySQL","MySQL"
```

In templates the key is referenced as `{KEY}` and resolved by `translateHtml()` in
`comode.php`.

## Files present in this repo

- `en.lang.txt` / `it.lang.txt` — the full set of core labels (~580 rows), used at runtime
  by the framework core during development/testing.
- `base.en.lang.txt` / `base.it.lang.txt` — a minimal subset (~220 rows) of only the labels
  needed before/during installation. **These are the two files `copiacore.php` copies into
  child projects** (see [DEPLOYMENT.md](DEPLOYMENT.md)), not the full `en/it.lang.txt`
  files.

## Convention in child projects

Every child project keeps its own set of labels (core + domain-specific) starting from the
`base.*.lang.txt` files received from the core. Some projects add per-module files, e.g.
`timynce` uses `base.{en,it}.lang.txt` (core) plus `timy.{en,it}.lang.txt` (timesheet-specific
labels, e.g. `Supplier`, `Revenues`, `Costs`). Domain-specific labels belong in the
project's/module's own lang file, not in the core's.

**The core's primary language is Italian**: when adding a new label, add it to both
`it.lang.txt` and `en.lang.txt` (or the equivalent `base.*`/module files).
